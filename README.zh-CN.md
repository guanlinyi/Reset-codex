# Reset-codex

[English](README.md) | 简体中文

面向 Windows 11 的 Codex 额度面板与聊天接续工具。查看 5 小时和每周额度，用 Psmux 管理原生 Codex 终端，并在额度恢复后继续任务。应用界面名称为 **Reset**，默认中文，支持英文。不依赖 VS Code。

## 开始使用

[下载 Windows x64 便携包](release/Reset-codex-windows-x64.zip)

1. 解压后双击 `Reset.exe`。保留同目录的辅助程序和 `_internal`；便携包已附带 Python 和 Psmux。
2. 等待自动检测。已有 Codex 登录会自动复用，最近的本机 CLI 聊天按标题和完整会话 ID 列出。缺少 Codex 或 Windows Terminal 时，在“连接与启动”中安装或选择程序。
3. 在“选择聊天窗口”中保留默认聊天或另选聊天，点击“查看”。聊天显示在黑色 Windows Terminal 中。
4. 按需修改“推进指令”，设置等待额度恢复的次数，点击“启动持续推进”。软件会自动输入并回车提交指令；后续接续使用同一条指令。

默认推进指令：

> 持续推进至额度耗尽，确认独立任务结束后保存交接

指令可编辑，最多 2000 字。模型只有一个可选修改入口：不选择就沿用该聊天原来的模型。

## 持续推进

- **恢复次数默认 0**：当前额度耗尽后停止自动推进。选择 1，则等待一次已确认的 5 小时额度恢复，继续一轮；其他次数依此类推。每次恢复只提交一次指令，不能只根据倒计时认定额度已经恢复。
- **目标恢复弹窗默认自动取消**：出现 `Resume goal / Leave paused` 时选择 `Leave paused`，再发送推进指令。取消勾选后遇到该弹窗会提示手动处理。
- **Codex 更新默认自动处理**：识别受支持的官方更新菜单后选择更新，确认成功、旧 Codex 退出且原终端回到空闲提示符后，以原会话 ID 重新进入，再发送推进指令。取消勾选后会暂停等待处理。未知菜单、更新失败或超时不会无限重试。
- **自动关机默认关闭**：勾选后，在最后一轮额度耗尽且终端空闲时开始 60 秒可取消倒计时；关机前重新确认额度。选择 0 次表示当前轮结束后关机，选择 1 次表示恢复一次并用完最后一轮后关机。
- **取消持续推进**：停止后续自动接续和自动关机。已经发送给 Codex 的任务仍在终端运行；要结束任务和终端，请使用对应聊天的“结束”。

持续模式运行期间保持电脑唤醒。系统关机、终端关闭、权限提示或需要人工处理的问题可能中断流程；重新启动 Reset 不会擅自恢复持续任务。完整的真实额度耗尽 → 等待 → 恢复流程仍需进一步实机验证，见 [验证范围](VALIDATION.md)。

## 终端管理

“查看”复用已运行的 Reset Psmux 会话；没有运行时新建终端。同一会话的启动通过锁串行处理，已连接时优先显示原窗口，不另开 Codex。

“正在运行的聊天”显示 Reset 管理的 Psmux 终端，包括标题、完整会话 ID、PID 和连接状态。“结束”先确认，再停止该聊天的持续推进并关闭对应终端；保存的聊天记录保留。批量结束只处理确认没有前端连接的后台会话，执行前再次核实身份，已连接或已变化的目标会跳过。

对于外部终端，软件会结合启动参数、已登记身份及持续持有的可写会话文件句柄识别会话 ID，仅检查文件名和句柄权限，不读取文件内容。确认同一会话在外部运行时，会提示先自行关闭原 Codex。其他身份不明的进程不会锁住所有聊天；权限不足、自定义数据目录或无法识别的客户端仍可能导致检测不完整。

关闭聊天最后一个前端终端，会由 Psmux 结束对应后台会话；最小化不受影响。窗口已关闭、终端登记已变化或输入框有其他未提交内容时，不会盲目覆盖输入。若上次留下的正是当前设置中的同一条指令，软件会尝试提交该草稿，而不是重复输入。

## 连接、网络与开机启动

“连接与启动”中的 **＋／−** 可展开或收起检查项。软件优先复用官方 Codex 已有登录；尚未登录时，点击“登录 ChatGPT”并由使用者完成官方授权。它不会导入 ChatGPT 网页版的全部聊天。

**代理不是必需项。** 未配置代理时直接连接；已有环境代理或 Windows 系统代理时自动跟随，也支持发现部分正在运行的本地代理客户端端口。网络确实需要代理且自动发现失败时，再填写 HTTP 代理地址。公开默认配置没有个人端口，代理地址不支持内嵌账号密码。额度查询失败不会阻止本地聊天目录显示。

开启“开机打开 Reset”后，登录 Windows 只启动 Reset；不自动恢复聊天或发送任务。缺少依赖、需要系统提权或权限标记修复时，界面提供对应操作，由使用者确认 Windows 授权。权限修复仅针对软件自身可执行文件，不放宽用户目录权限或 Codex 沙箱。

## 本机数据与隐私

个人配置位于 `%LOCALAPPDATA%/Reset/config.local.json`，运行状态和界面数据也保存在本机应用数据目录。推进指令和勾选项保存在本机的持续推进状态中，不写入公开默认配置或便携包。同目录 `config.local.json` 仍可作为高级覆盖配置；用户应用数据目录中的配置优先。

额度、模型和最近聊天标题通过本机官方 Codex app-server 获取，不直接读取认证文件。自动处理终端弹窗和验证发送时，会在本机读取所选 Psmux 终端的可见屏幕，其中可能包含聊天正文；Reset 不将这些捕获内容上传或保存为日志。发送给 Codex 的指令由官方 Codex 按其正常机制处理。

不要提交个人配置、登录文件、浏览器数据、运行记录或个人进展文档。仓库提供忽略规则和公开内容检查。

| 高级设置 | 说明 |
|---|---|
| `codex_path`、`windows_terminal_path`、`browser_path`、`psmux_path` | 自动发现失败时指定程序路径 |
| `workspace` | 留空显示全部本机 CLI 聊天；填写后按目录过滤 |
| `thread_id` | 可选默认聊天；留空选择最近可用聊天 |
| `language` | `zh` 或 `en`；界面选择在本机记忆 |
| `recovery_limit` | 默认等待恢复次数，0–100 |
| `proxy_host`、`proxy_port` | 可选，两项同时填写；留空自动发现或直接连接 |
| `require_admin` | 检查管理员权限和实际完整性级别 |
| `startup_delay_seconds` | 开机启动延迟，默认 10 秒 |

## 开发与备用命令

Windows 11 x64，Python 3.11 或更新版本。建议使用独立 Conda 环境。附带便携包使用 Python 3.12。

从源码运行：

```powershell
python -m pip install -r requirements.txt
python -B main.py
```

构建新的便携目录：

```powershell
python -m pip install -r requirements-build.txt
python -B build.py
```

输出为 `release/Reset`。构建命令不覆盖已有目录，可用 `--output` 指定新的输出位置。`Reset.exe` 是桌面入口，`ResetTerminal.exe` 用于保留原生终端输入输出，二者共享控制逻辑。

以下命令是界面操作的备用方式：

```powershell
.\ResetTerminal.exe --diagnose
.\Reset.exe --install-startup
.\Reset.exe --disable-startup
```

权限修复备用方式：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\repair-permissions.ps1
```

修复仅调整本软件可执行文件的完整性标记，不递归修改目录、不放宽用户目录 ACL、不修改 Codex 沙箱。脚本核验 Psmux 签名。安全标签属于本地文件系统；新生成或复制的文件可能继承目标目录的限制，修过旧副本不等于新副本已修复，也不是每次启动都要重复修复。

验证源码与公开内容：

```powershell
python -B -m unittest discover -s tests -q
python -B audit_public.py
```

状态机、取消、网络发现、配置和界面有自动化检查；完整的真实额度耗尽、等待和恢复周期仍需实机验收。Codex 升级若改变原生交互格式，软件会停止等待处理。
